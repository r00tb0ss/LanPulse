# LanPulse 1.39.25

## Public IP scan reliability and visibility
- Streams live Nmap progress into the Threat Map public-IP workflow, including carriage-return progress updates.
- Displays completed Nmap findings and target reachability instead of leaving the interface at a generic started state.
- Distinguishes an unreachable target from a reachable host with closed ports.
- Keeps public scans explicitly authorized, manually initiated, bounded, and separate from LAN discovery.
- Adds global and per-target cooldowns, bounded scan history, and audit coverage for public Nmap and OpenVAS activity.

## Clearer scanning workflows
- Separates LAN device scanning from authorized public-IP scanning in the IP panels.
- Removes the overlapping OpenVAS choice from the LAN scan panel.
- Removes the duplicate OpenVAS scan button from Vulnerabilities device rows while retaining the device-detail and Scanner management entry points.
- Improves Threat IP panel spacing and mobile card layout.

## Complete AI evidence with explicit cloud consent
- Preserves retained threat, honeypot, Cowrie session/command, captured-sample, YARA, runtime telemetry, and authorized scan evidence for AI investigations.
- Loads retained Cowrie sessions in bounded 200-record database pages, batches associated sample metadata lookups, and uses an aggregate size preflight to reject evidence sets that exceed the in-memory safety limit.
- Uses conservative token/byte budgets and fails explicitly when the complete requested evidence cannot safely fit, rather than silently dropping records.
- Requires explicit consent before raw security evidence is sent to hosted AI providers, with clear disclosure and revocation behavior.
- Revokes prior cloud-evidence consent when the AI destination changes.

## Validation
- CI validates Python, shell, and JavaScript syntax, unit tests, release-note presence, and browser views.
- The release workflow publishes the ZIP and SHA-256 checksum only after successful CI for the latest main commit.
