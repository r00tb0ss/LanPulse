# LanPulse 1.25.38

## Update checks keep working when GitLab says "too many requests"
GitLab limits how many anonymous requests one network address can make, and a busy address could see **Settings > Update > Check for updates** fail with "GitLab answered 429". The check now reads a small file from the LanPulse project page first, which isn't subject to that limit, and only asks GitLab's API if that fails. If GitLab does answer 429, the message now says so and to try again in a minute, and the last result is reused when there is one. Downloads are still limited to the release sites over HTTPS, and every update still goes through the same checks as a file you upload yourself. You can always choose a file manually instead.

## For maintainers
`.gitlab-ci.yml` now publishes a GitLab release with `lanpulse.zip` attached whenever `VERSION` in `app.py` changes on `main` (the `publish-release` job), and the `pages` job writes `latest.json` from that release for the updater to read. `tools/release_gitlab.py` still works for publishing by hand; if you do, re-run the pipeline on `main` afterwards so `latest.json` picks the release up.

## Upgrade
Settings > Update > Check for updates > Download > Install. Your devices, history, settings and login are kept.
