# LanPulse 1.39.16

## Added
- **Honeypot C2 Intelligence** brings extracted indicators and observed network activity together while keeping the evidence types distinct.
- **Isolated runtime telemetry** adds a passive sensor for DNS queries and answers, TCP/UDP connection attempts, TLS SNI, and HTTP Host observations. Events are linked to a captured sample SHA-256 and a specific analysis run.
- Dedicated runtime sensor registration, one-time credentials, revocation, and a guided setup workflow in the Honeypot interface.
- Runtime sensor tooling is included with the LanPulse installation.

## Improved
- AI honeypot analysis now uses captured session evidence more carefully, expands behavior-based findings, and validates proposed MITRE ATT&CK technique IDs against supported evidence.
- C2 indicator handling and campaign correlation distinguish candidate indicators from observed activity and avoid presenting shared infrastructure or text matches as proof of a common operator.
- DNS answers are correlated with queried hostnames so analysts can see which IP addresses a sample's DNS lookups resolved to.
- C2 evidence cards, sensor instructions, and related Honeypot views have been refined for clearer navigation and responsive layouts.

## Security and reliability
- Runtime telemetry uses dedicated sensor authentication; stored sensor credentials are hashed rather than kept in plaintext.
- Sensor administration and runtime observations are protected by dashboard authentication. Ingestion validates sensor credentials, event fields, timestamps, sample hashes, and batch sizes.
- Runtime telemetry includes request rate limiting, duplicate-event handling, bounded retention, and a hard event-count ceiling.
- The passive sensor requires HTTPS by default, checks private token-file permissions, and records only selected network metadata—not packet captures, request bodies, or credentials.
- Malformed URLs and untrusted attacker-controlled text are handled more defensively in C2 and AI analysis paths.

## Important analysis notes
- Extracted URLs, domains, IP addresses, commands, and strings are candidate indicators—not proof that a sample executed them or contacted them.
- Runtime events show observed DNS activity or connection attempts from the analysis VM. They do not alone establish that a destination is command-and-control.
- Shared indicators and infrastructure do not identify a malware author or operator.
- Run samples only in a disposable, isolated malware-analysis environment. Keep it off trusted and household networks, restrict egress to a controlled gateway or sinkhole, and allow only the required telemetry path to LanPulse.
