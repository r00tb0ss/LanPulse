# 1.26.0

- **Honeypot sensors (optional).** Add a more realistic honeypot next to the built-in one: a Raspberry Pi, any Linux box or a container running Cowrie (a fake SSH/Telnet server). The built-in light honeypot is unchanged and keeps working on its own.
- **Add sensor button** (Honeypot > Captured attacks and malware > Sensors). Name it, pick Raspberry Pi / Linux or container, and paste the one-line command on the sensor. It installs everything, gives the sensor its own key (removable at any time), checks the installer against a checksum shown in the command, and turns green when the sensor reports in. LanPulse never stores a password or SSH key for the sensor.
- **Sessions:** every attacker connection with the logins tried, a command-by-command replay, plain-language tags mapped to MITRE ATT&CK, and a 0-100 danger score.
- **Samples:** every file an attacker downloads or uploads, analysed without ever running it: hashes, file type (including CPU type for Linux programs), entropy, readable strings, addresses, wallets and keys inside, family hints (Mirai-style, miners, ...) and where it came from. Addresses are shown defanged, and the files are stored privately and never offered for download.
- New alert when a new malware sample is captured.
- Safety: size caps, per-minute rate limits and a stored-session cap protect LanPulse from a flooding or hijacked sensor.
