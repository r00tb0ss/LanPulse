# LanPulse 1.34.19

## Security hardening
- The first dashboard login can no longer be set from another device on the network. Set it on the LanPulse machine itself: the installer offers it, or run `app.py --set-password`. Changing an existing login from the dashboard works as before.
- Saved keys and passwords are forgotten when the address they are sent to changes and the secret is not typed in again. This covers UniFi, Pi-hole, the AI analyst, email, ntfy and IRC. After moving one of these to a new address, enter its key or password again.
- Device discovery only fetches a UPnP description from the device that announced it; addresses that hide a second host are refused.
- Sign-in and honeypot event requests are size-limited before they are read, and other dashboard requests are refused when they are unreasonably large.
- Signing out now ends every session, so a copied session cookie stops working. You will need to sign in again on your other devices.
- Alert addresses for ntfy and webhooks must be web addresses (http or https).
- Without a login, quiet mode can be set for at most 24 hours instead of 7 days.

## Fixes
- Malformed requests to the account, block, unblock and syslog-allow actions return a clear error instead of a server error.
- The Update tab no longer re-reads and re-hashes a staged update on every status check.

## Not changed in this release
- Updates are still verified by checksum, not by a publisher signature.
- Ingest keys are still accepted in the request address for existing sensors, and webhook addresses are still shown in Settings.

## Tests
- Adds coverage for forgotten secrets, alert address checks, the quiet-mode cap, UPnP address checks and sign-out.
- The merge-request pipeline runs Python compilation, JavaScript syntax checks, asset-reference validation, and the unit test suite.
