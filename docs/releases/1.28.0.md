# LanPulse 1.28.0

## Fix: no Windows XP vulnerabilities for a device with no open ports

A PC whose firewall blocks every port could keep an old or weak OS guess (for example "Windows XP SP3") and be listed
with old-Windows CVEs. LanPulse now ignores the OS guess for CVE matching and the end-of-life Windows warning when a
device has no open ports, only trusts nmap's OS match for CVEs at 85% confidence or better, and clears the stored guess
when a scan finds no open ports.

## FTP and web decoys for honeypot sensors

A honeypot sensor can now watch more than SSH and Telnet. In **Honeypot > Captured attacks and malware > Sensors >
Add sensor > Customize** there is a new **More services** section:

- **FTP decoy:** accepts any login and keeps the files that are uploaded, so you can see what is being dropped.
- **Web decoy:** logs exploit attempts, login forms and suspicious headers, and keeps files sent with `PUT`, `POST` or an
  upload form.

They are one small program (Python standard library only) that runs next to Cowrie as its own service on a Raspberry Pi or
Linux box, or as a third container. Their sessions and files appear with the SSH and Telnet ones, with the same static
analysis, and a session shows which protocol it used.

They are built to be safe to leave on the internet: uploads are stored under their hash and never run, opened or served;
FTP active mode is refused so the sensor never connects out; ports are 1024 and up (forward 21 and 80 on your router to
2121 and 2180, and the 20 FTP upload ports after 2121); and connections, file sizes, disk use and the number of
reported sessions are all capped. Plain web page loads from scanners are answered but not listed.

The forwarding note in the generated command now covers these ports too. Nothing changes for sensors you already set up
until you run an Add sensor command with the new settings, and the built-in light honeypot is untouched.
